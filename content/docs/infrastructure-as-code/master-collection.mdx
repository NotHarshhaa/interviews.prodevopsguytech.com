# Master Collection

<Callout type="info" title="Overview">
The complete collection for Infrastructure as Code: 200 questions drawn straight from the source bank. The level pages curate a learning path through it; this page holds everything, so nothing is more than one scroll away.
</Callout>

<Steps>

<Step>
**What is Infrastructure as Code (IaC) and what core problems does it solve?**

Infrastructure as Code (IaC) is the practice of provisioning, configuring, managing, and versioning compute, storage, and networking resources using machine-readable definition files rather than manual console clicks. It eliminates human configuration errors, eradicates "Snowflake Servers," enforces version control, and allows tearing down and recreating entire production environments in minutes.
</Step>

<Step>
**Compare Declarative vs Imperative IaC with concrete examples.**

- **Declarative (e.g., Terraform, OpenTofu, Kubernetes YAML):** Declares **WHAT** the eventual infrastructure state should be. The engine computes dependencies and executes CRUD operations to match that state (`resource "aws_s3_bucket" "b" { ... }`).
- **Imperative (e.g., AWS CLI, Bash scripts, Python Boto3):** Specifies **HOW** to reach the state via sequential commands (`aws s3api create-bucket ...`). Re-running imperative scripts fails without explicit custom idempotency logic.
</Step>

<Step>
**What is Terraform State and why is it necessary?**

The Terraform state file (`terraform.tfstate`) is a JSON document that maps your declarative HCL configuration to real-world cloud resource IDs and attributes. It tracks resource dependencies, caches metadata for plan performance, and coordinates concurrent execution via state locking.
</Step>

<Step>
**Explain the core Terraform CLI workflow commands.**

1. `terraform init`: Initializes working directory, downloads provider plugins/modules, and configures remote backends.
2. `terraform validate`: Validates syntax and internal consistency of HCL files without cloud API calls.
3. `terraform plan`: Computes the execution plan by comparing code against state and live infrastructure.
4. `terraform apply`: Executes the changes required to reach desired state.
5. `terraform destroy`: Destroys all remote objects managed by the state file.
</Step>

<Step>
**Compare Terraform `count` vs `for_each`.**

- **`count`:** Creates resources indexed by an integer list (`[0, 1, 2]`). Removing an item from the middle causes Terraform to reindex and force-recreate all subsequent resources.
- **`for_each`:** Creates resources keyed by unique map or set strings (`["web", "api", "db"]`). Adding or removing an item affects *only* that specific key without destroying others.
</Step>

<Step>
**What is a Terraform Module and how does it enforce DRY principles?**

A container for multiple resources used together. Modules package reusable, standardized infrastructure components (VPCs, EKS clusters) with input variables and outputs, avoiding code duplication across environments.
</Step>

<Step>
**Compare Terraform Variables, Locals, and Outputs.**

- **Variables (`variable`):** Input parameters passed into modules to customize behavior.
- **Locals (`locals`):** Internal reusable constants or computed expressions scoped strictly to the current module.
- **Outputs (`output`):** Return values exposed by a module to the root module or CLI stdout.
</Step>

<Step>
**What is a Remote Backend and why is State Locking mandatory?**

A remote storage location (e.g., AWS S3 + DynamoDB / Terraform Cloud) for state files. State locking prevents race conditions and corrupted state files by ensuring only one engineer or pipeline can execute `apply` at any time.
</Step>

<Step>
**What is OpenTofu and why was it created?**

In August 2023, HashiCorp switched Terraform's license from open-source MPL 2.0 to the Business Source License (BSL 1.1). OpenTofu was created by the Linux Foundation and community as a 100% open-source, backward-compatible fork of Terraform.
</Step>

<Step>
**What is Configuration Drift in IaC and how is it resolved?**

Discrepancies between declared IaC code and actual live cloud resources caused by manual console edits. Resolved by running automated scheduled drift detection (`terraform plan -detailed-exitcode`) and applying code to reconcile drift.
</Step>

<Step>
**What is the `moved` block in Terraform?**

Allows refactoring resources (renaming or moving into child modules) without destroying and recreating live cloud resources:
```hcl
moved {
  from = aws_instance.web
  to   = module.compute.aws_instance.web
}
```
</Step>

<Step>
**What is the `import {}` block in Terraform 1.5+?**

A declarative block that imports existing cloud resources into Terraform state natively in code, generating configuration templates automatically via `terraform plan -generate-config-out=generated.tf`.
</Step>

<Step>
**What are Terraform Custom Preconditions and Postconditions?**

Declarative validation rules defined inside `lifecycle` blocks that validate assertions before or after resource provisioning:
```hcl
lifecycle {
  precondition {
    condition     = data.aws_ami.ubuntu.architecture == "x86_64"
    error_message = "Selected AMI must be x86_64."
  }
}
```
</Step>

<Step>
**What is Terragrunt and what problems does it solve?**

A thin wrapper for Terraform/OpenTofu providing DRY remote state backend definitions, automated module dependency execution (`terragrunt run-all apply`), and mock outputs for plan evaluations.
</Step>

<Step>
**What are Terraform Dynamic Blocks?**

Constructs repeatable nested configuration blocks (e.g., multiple `ingress` rules inside an `aws_security_group`) dynamically from a list or map variable.
</Step>

<Step>
**Compare `.terraform.lock.hcl` vs `terraform.tfstate`.**

- **`.terraform.lock.hcl`:** Dependency lock file recording exact provider plugin versions and cryptographic hashes; committed to Git.
- **`terraform.tfstate`:** Records live cloud resource IDs and attributes; stored in an encrypted remote backend, never committed to Git.
</Step>

<Step>
**How do you protect sensitive values in Terraform?**

Mark variables/outputs with `sensitive = true` to prevent display in CLI stdout or CI logs. *Caveat: State files still contain plain text sensitive values and must be stored in KMS-encrypted S3 backends with restricted IAM.*
</Step>

<Step>
**What is Terratest?**

A Go library developed by Gruntwork that provisions real cloud infrastructure via Terraform, executes integration tests against live endpoints, and tears down resources.
</Step>

<Step>
**What is Crossplane?**

A CNCF open-source project that turns Kubernetes into a universal cloud control plane, allowing platform teams to manage cloud resources (S3, RDS) as Kubernetes Custom Resources (CRDs).
</Step>

<Step>
**What is Pulumi?**

An open-source IaC engine that allows defining cloud infrastructure using general-purpose programming languages (**TypeScript, Python, Go, C#**) with full IDE auto-complete and unit test support.
</Step>

<Step>
**What is Ansible and how does its agentless architecture work?**

An open-source automation and configuration management tool that connects to target nodes over standard SSH (Linux) or WinRM (Windows) without installing daemons or agents on managed nodes.
</Step>

<Step>
**What is Ansible Idempotency?**

The property of an Ansible playbook where executing it once or multiple times produces the exact same end state without unintended side effects.
</Step>

<Step>
**Compare Terraform vs Ansible.**

Terraform is optimized for **infrastructure provisioning** (orchestrating VPCs, EKS, RDS) using declarative state; Ansible is optimized for **configuration management** (installing packages, configuring OS files) on running servers.
</Step>

<Step>
**What is `terraform refresh`?**

Queries cloud APIs to update the local state file with real-world resource attributes without modifying live infrastructure.
</Step>

<Step>
**What is a Terraform Data Source?**

A read-only query that fetches attributes from external cloud resources defined outside the current configuration (e.g., querying the latest official Ubuntu AMI ID).
</Step>

<Step>
**What is `terraform taint` vs `terraform apply -replace`?**

`terraform taint` is legacy; `terraform apply -replace="aws_instance.web"` forces recreation of a specific resource in a single step without modifying state beforehand.
</Step>

<Step>
**What are Terraform Workspaces?**

Separate state files managed from a single working directory (`terraform workspace select staging`). Best for ephemeral feature branches; directory-based layouts are preferred for production isolation.
</Step>

<Step>
**What is `terraform fmt`?**

Automatically rewrites all `.tf` files in the directory to conform to canonical Terraform style and indentation standards.
</Step>

<Step>
**What is `terraform graph`?**

Generates a visual Directed Acyclic Graph (DAG) of all resource dependencies in DOT format for graphviz visualization.
</Step>

<Step>
**What is Checkov?**

A static code analysis tool scanning Terraform, CloudFormation, and Kubernetes manifests in CI pipelines for security misconfigurations and compliance violations.
</Step>

<Step>
**What is tfsec / Trivy for IaC?**

Fast static security scanners that parse HCL code and flag security risks (unencrypted storage, public S3 buckets, open security groups) before deployment.
</Step>

<Step>
**What is Infracost?**

A CLI tool that parses Terraform code in CI/CD pull requests, calculates the exact monthly cost delta of proposed infrastructure changes, and posts an interactive breakdown comment onto the PR.
</Step>

<Step>
**What is Atlantis for Terraform?**

A self-hosted application that executes `terraform plan` on PR creation, posts the diff, locks state, and applies changes only when authorized reviewers comment `atlantis apply`.
</Step>

<Step>
**What is HashiCorp Cloud Platform (HCP) Terraform / Terraform Cloud?**

A managed collaborative platform providing remote execution runners, centralized state locking, private module registries, cost estimation, and Sentinel policy enforcement.
</Step>

<Step>
**What is Spacelift?**

A collaborative infrastructure orchestration platform for Terraform, OpenTofu, Pulumi, and CloudFormation with built-in OPA policy enforcement and drift detection.
</Step>

<Step>
**What is the `ignore_changes` lifecycle rule in Terraform?**

Instructs Terraform to ignore updates to specific resource attributes caused by external systems or autoscaling (e.g., `lifecycle { ignore_changes = [tags, desired_capacity] }`).
</Step>

<Step>
**What is `create_before_destroy` lifecycle rule?**

Inverts Terraform's default replacement behavior by creating the replacement resource *first* before destroying the old resource, minimizing service downtime.
</Step>

<Step>
**What is `prevent_destroy` lifecycle rule?**

Causes Terraform to reject any execution plan that would destroy the annotated critical resource (e.g., production database).
</Step>

<Step>
**What is a Terraform Provider Alias?**

Allows configuring multiple instances of the same provider (e.g., deploying resources across multiple AWS regions or accounts in a single configuration) using `alias = "west"`.
</Step>

<Step>
**What is Terraform Variable Precedence?**

Evaluated with increasing priority: Environment variables (`TF_VAR_name`) $\rightarrow$ `terraform.tfvars` $\rightarrow$ `terraform.tfvars.json` $\rightarrow$ `*.auto.tfvars` $\rightarrow$ CLI flags (`-var`).
</Step>

<Step>
**What is `terraform state rm` vs `terraform state mv`?**

- **`state rm`:** Removes a resource from state; live cloud resource is **not deleted**, Terraform simply stops managing it.
- **`state mv`:** Renames or moves a resource within state without destroying or recreating it.
</Step>

<Step>
**What is Terraform Provider Mirroring?**

Configuring CLI config (`.terraformrc`) to read pre-downloaded provider binaries from local disk or private registries in air-gapped environments without internet access.
</Step>

<Step>
**What is Terraform Blast Radius and how do you minimize it?**

The maximum potential damage from a failed apply. Minimized by breaking monolithic state files into layered, decoupled state files (Networking $\rightarrow$ Data $\rightarrow$ Compute $\rightarrow$ App).
</Step>

<Step>
**What is Ansible Playbook vs Role vs Collection?**

- **Playbook:** YAML file mapping tasks and configuration states to target hosts.
- **Role:** Reusable directory packaging tasks, handlers, variables, and templates.
- **Collection:** Modern packaging format containing multiple roles, custom Python modules, and plugins.
</Step>

<Step>
**What is Ansible Inventory (Static vs Dynamic)?**

- **Static:** INI/YAML file listing static hostnames and IP addresses.
- **Dynamic:** Plugin querying cloud APIs (AWS EC2, Azure) to dynamically discover target instances based on tags.
</Step>

<Step>
**What is Ansible Vault?**

Encrypts sensitive variables, files, or playbooks with AES-256 (`ansible-vault encrypt secrets.yml`).
</Step>

<Step>
**What is OpenTofu State Encryption?**

A native OpenTofu feature allowing state files and plan files to be encrypted end-to-end at the client level using AES-GCM or AWS KMS before being transmitted to remote backends.
</Step>

<Step>
**What is Terraform Plugin Framework (v6)?**

Modern Go SDK for authoring Terraform providers with native support for structured types, nested object attributes, and gRPC protocol buffers.
</Step>

<Step>
**What is Crossplane Composite Resource (XR) vs Claim (XRC)?**

- **XRD:** Platform team defines the abstract schema (`kind: DatabaseInstance`).
- **Composition:** Binds XRD to concrete cloud resources (RDS, Security Group, KMS Key).
- **Claim:** Developers request a database via a simple 5-line Kubernetes manifest without knowing AWS details.
</Step>

<Step>
**What is HashiCorp Sentinel?**

A proprietary Policy as Code framework embedded in Terraform Cloud that enforces compliance rules (e.g., blocking non-whitelisted EC2 instance types) before apply.
</Step>

<Step>
**What is Open Policy Agent (OPA) / Conftest for Terraform?**

Evaluates exported Terraform execution plans in JSON format against declarative **Rego** security policies in CI pipelines.
</Step>

<Step>
**What is KubeVela?**

A modern application delivery platform on Kubernetes built on the Open Application Model (OAM) providing application-level abstractions over underlying infrastructure.
</Step>

<Step>
**What is Terraform `terraform_remote_state` Data Source?**

A data source that reads root output values from a separate remote state file, enabling loose coupling between infrastructure layers.
</Step>

<Step>
**What is Terraform `templatefile()` function?**

Renders an external template file with dynamic variable interpolation (e.g., rendering `user_data.sh` scripts).
</Step>

<Step>
**What is Terraform `null_resource` vs `terraform_data`?**

- **`null_resource` (Legacy):** Requires downloading a separate provider plugin to execute local scripts (`local-exec`).
- **`terraform_data` (Built-in since 1.4):** Native replacement for `null_resource` requiring zero external provider downloads.
</Step>

<Step>
**What is `local-exec` vs `remote-exec` Provisioner?**

- **`local-exec`:** Runs a local command on the machine executing Terraform.
- **`remote-exec`:** Connects to the provisioned remote instance over SSH/WinRM to execute shell commands. *Best practice: Avoid provisioners; use cloud-init or Ansible.*
</Step>

<Step>
**What is Terraform Provider Dependency Lock?**

Records exact cryptographic provider checksums in `.terraform.lock.hcl` to ensure all team members and CI runners download identical provider binaries.
</Step>

<Step>
**What is Terraform Self Reference (`self`)?**

An object referring to the resource's own attributes within `provisioner` or `connection` blocks.
</Step>

<Step>
**What is Terraform Module Registry?**

A public or private repository for discovering and distributing versioned, reusable Terraform modules.
</Step>

<Step>
**What is `terraform force-unlock`?**

Releases a stuck remote state lock in DynamoDB/Consul when a previous run crashed unexpectedly: `terraform force-unlock <LOCK-ID>`.

##  **Part 2: Advanced Terraform, OpenTofu & Terragrunt (Questions 61–130)**
</Step>

<Step>
**Explain the step-by-step lifecycle of `terraform plan`.**

1. Loads configuration files and builds the Dependency Graph (DAG).
2. Reads the current state file from the remote backend.
3. Refreshes state: Queries cloud APIs to fetch current live resource attributes.
4. Compares live state against declared code to determine CRUD deltas (Add, Change, Destroy).
5. Outputs the execution plan diff.
</Step>

<Step>
**What is Terraform Graph Cycle and how is it resolved?**

A circular dependency error where Resource A depends on Resource B, and Resource B depends on Resource A. Resolved by decomposing circular references (e.g., creating security groups first, defining `aws_security_group_rule` as independent resources).
</Step>

<Step>
**How do you implement Zero-Downtime AMI updates in Auto Scaling Groups using Terraform?**

1. Use `aws_launch_template` with `create_before_destroy = true`.
2. Configure `instance_refresh` block in `aws_autoscaling_group` to orchestrate rolling instance replacements automatically upon template updates.
</Step>

<Step>
**What is the difference between `lookup()`, `try()`, and `can()` functions in HCL?**

- **`lookup(map, key, default)`:** Retrieves value from a map with a fallback default.
- **`try(expr1, expr2, ...)`:** Evaluates expressions sequentially, returning the first one that does not produce an error.
- **`can(expr)`:** Evaluates an expression and returns `true` if it succeeds without errors, or `false` otherwise.
</Step>

<Step>
**What is OpenTofu Early Evaluation of Variables?**

An OpenTofu feature allowing variables and locals to be evaluated during backend configuration blocks, eliminating hardcoded backend S3 bucket names.
</Step>

<Step>
**What is Terragrunt `read_terragrunt_config()`?**

Imports helper HCL files into a Terragrunt configuration, allowing centralized sharing of environment variables, AWS account IDs, and common tags.
</Step>

<Step>
**What is Terragrunt `dependency` Block?**

Declares a dependency on another module, automatically resolving remote outputs and establishing execution order (`terragrunt run-all apply`).
</Step>

<Step>
**What are Terragrunt `mock_outputs`?**

Supplies mock return values during `terragrunt plan` when an upstream dependency module has not yet been applied, preventing plan failures.
</Step>

<Step>
**How do you implement automated Terraform Drift Detection in CI/CD?**

A scheduled cron pipeline executing:
```bash
terraform plan -detailed-exitcode -no-color
```
- Exit 0: Succeeded, no differences.
- Exit 1: Malformed configuration or API error.
- Exit 2: Succeeded with non-empty diff (Drift Detected $\rightarrow$ alerts Slack).
</Step>

<Step>
**How do you test Terraform modules with Terratest in Go?**

```go
func TestVpcModule(t *testing.T) {
    terraformOptions := terraform.WithDefaultRetryableErrors(t, &terraform.Options{
        TerraformDir: "../modules/vpc",
        Vars: map[string]interface{}{"cidr_block": "10.0.0.0/16"},
    })
    defer terraform.Destroy(t, terraformOptions)
    terraform.InitAndApply(t, terraformOptions)
    vpcId := terraform.Output(t, terraformOptions, "vpc_id")
    assert.NotEmpty(t, vpcId)
}
```
</Step>

<Step>
**What is Policy as Code with Rego and Conftest?**

Export plan to JSON (`terraform show -json tfplan.binary > tfplan.json`), then evaluate against Rego rules in CI:
```rego
package main
deny[msg] {
    resource := input.resource_changes[_]
    resource.type == "aws_s3_bucket"
    not resource.change.after.server_side_encryption_configuration
    msg := "S3 buckets must have server-side encryption enabled!"
}
```
</Step>

<Step>
**What is OpenTofu Provider Plugin Signing and Verification?**

OpenTofu verifies cryptographic PGP signatures and SHA256 checksums of all downloaded provider binaries against registry public keys before loading them into memory.
</Step>

<Step>
**What is Terraform Module Semantic Versioning?**

Pinning module sources to specific SemVer versions (`source = "terraform-aws-modules/vpc/aws?version=5.1.0"`) to prevent untested breaking changes from being applied automatically.
</Step>

<Step>
**What is the difference between `merge()` and `concat()` in HCL?**

- `merge(map1, map2)`: Combines two or more maps into a single map (keys overwritten by rightmost map).
- `concat(list1, list2)`: Combines two or more lists into a single sequential list.
</Step>

<Step>
**What is Terraform Custom Provider development?**

Authoring custom Go plugins using the HashiCorp Terraform Plugin Framework that implement `Create`, `Read`, `Update`, and `Delete` methods against internal proprietary APIs.

##  **Part 3: Crossplane, Pulumi, Ansible & Enterprise Scenarios (Questions 76–200)**
</Step>

<Step>
**Scenario: An engineer accidentally ran `terraform destroy` against staging and cancelled it midway. How do you recover?**

1. Release any stuck state locks: `terraform force-unlock <LOCK-ID>`.
2. Sync state: `terraform refresh`.
3. Generate targeted recovery plan: `terraform plan -out=recovery.plan`.
4. Apply plan to recreate destroyed resources and restore consistency: `terraform apply recovery.plan`.
</Step>

<Step>
**Scenario: Refactor a monolithic 500-resource Terraform state into 5 decoupled state files with zero downtime.**

1. Backup production state file.
2. Create target directory structure (`01-network/`, `02-database/`, `03-compute/`).
3. Migrate resources using `terraform state mv -state=monolith.tfstate -state-out=02-database/terraform.tfstate <source> <dest>`.
4. Initialize remote S3 backends in each new directory.
5. Verify with `terraform plan` in each directory to confirm **0 to add, 0 to change, 0 to destroy**.
</Step>

<Step>
**Scenario: A live production AWS S3 bucket containing 50TB of data was created manually. Bring it under Terraform management with zero data loss risk.**

1. Declare resource in HCL: `resource "aws_s3_bucket" "prod_data" { bucket = "company-prod-data" }`.
2. Import resource via `import {}` block (Terraform 1.5+).
3. Run `terraform plan` and reconcile attributes until plan shows **0 to add, 0 to change, 0 to destroy**.
4. Apply to bind state.
</Step>

<Step>
**Compare Crossplane vs Terraform at enterprise scale.**

- **Terraform:** Pipeline-driven batch execution; drift detected only on pipeline runs.
- **Crossplane:** Continuous control plane loop inside Kubernetes; continuously auto-heals drift and provides native Kubernetes CRD abstractions for developers.
</Step>

<Step>
**How do you structure a production multi-environment Terragrunt repository?**

```
root/
├── terragrunt.hcl               # Root config: S3 backend + provider generation
├── environments/
│   ├── dev/
│   │   ├── vpc/terragrunt.hcl
│   │   └── eks/terragrunt.hcl   # dependencies = ["../vpc"]
│   ├── staging/
│   └── prod/
└── modules/                     # Pure Terraform source modules
```
</Step>

<Step>
**How do you implement zero-trust secrets injection in Terraform without writing credentials to disk?**

Configure Terraform with the **HashiCorp Vault Dynamic Secrets Provider** (`data "vault_aws_access_credentials"`). Terraform requests short-lived (1-hour) cloud credentials generated on-demand by Vault, eliminating static keys entirely.
</Step>

<Step>
**Scenario: An engineer accidentally committed a production `.tfstate` file containing database passwords to GitHub. Walk through the complete response procedure.**

1. **Rotate All Secrets Immediately:** Rotate database master passwords, private TLS keys, and IAM credentials in the cloud provider.
2. **Purge Git History:** Use `git-filter-repo` to permanently strip `.tfstate` from all commits, branches, and tags. Force-push clean history.
3. **Move to Remote S3 Backend:** Configure remote encrypted S3 backend with DynamoDB locking.
4. **Enforce Prevention:** Add `*.tfstate` to `.gitignore` and configure GitHub Secret Scanning.
</Step>

<Step>
**What is Ansible Dynamic Inventory for AWS EC2?**

An Ansible plugin (`aws_ec2`) that queries AWS APIs to automatically group managed instances based on tags (e.g., `tag:Role_webservers`), eliminating static IP files.
</Step>

<Step>
**What is Pulumi Stack?**

An isolated, independently configurable instance of a Pulumi program (e.g., `dev`, `staging`, `prod`) with its own state and secrets encryption provider.
</Step>

<Step>
**What is Pulumi Crosswalk?**

A collection of high-level libraries (in TypeScript/Python) that implement well-architected cloud infrastructure best practices (e.g., creating a production VPC in 5 lines of code).
</Step>

<Step>
**What is Crossplane Provider Family?**

Modular, decoupled Crossplane provider packages (e.g., `provider-aws-s3`, `provider-aws-rds`) that install only the specific CRD controllers needed, avoiding cluster CRD limits.
</Step>

<Step>
**What is Crossplane Composition Function?**

Advanced gRPC functions (written in Go, Python, or KCL) that dynamically render complex compositions and conditionals that static YAML cannot express.
</Step>

<Step>
**What is Terraform Provider Factory in Unit Tests?**

Mocking cloud provider responses during unit tests to validate HCL logic and module transformations without making real cloud API calls.
</Step>

<Step>
**What is Terraform `replace_triggered_by`?**

A lifecycle attribute that forces a resource to be replaced whenever another specified resource changes (e.g., replacing an EC2 instance whenever a security group changes).
</Step>

<Step>
**What is OpenTofu Client-Side State Encryption Key Rotation?**

Rotating state encryption keys by declaring the new key in the OpenTofu configuration and running `tofu apply`, which re-encrypts the state file transparently.
</Step>

<Step>
**What is Ansible Asynchronous Actions (`async` and `poll`)?**

Running long-running tasks (e.g., database backups) asynchronously in the background while polling for status periodically.
</Step>

<Step>
**What is Ansible Handler?**

A special task executed only when notified by another task that resulted in a `changed` status (e.g., restarting Nginx only when `nginx.conf` changes).
</Step>

<Step>
**What is Ansible Serial Execution (`serial`)?**

Rolling execution of playbooks across batches of servers (e.g., `serial: "20%"`) to perform zero-downtime rolling updates.
</Step>

<Step>
**What is Ansible Tower / AWX?**

A web-based UI, REST API, and task engine for centrally managing Ansible playbooks, inventories, credentials, and RBAC across enterprise teams.
</Step>

<Step>
**What is Terraform `nonsensitive()` function?**

Exposes a sensitive value as non-sensitive when strictly required for display or passing to external non-sensitive modules.
</Step>

<Step>
**What is Terraform Output `depends_on`?**

Explicitly ordering output evaluation after specified resources complete provisioning.
</Step>

<Step>
**What is Terraform Module Nesting Best Practice?**

Keep module nesting to a maximum of 2 levels (Root $\rightarrow$ Child Module). Excessive nesting creates brittle dependency graphs and unmaintainable code.
</Step>

<Step>
**What is Terraform CLI Configuration (`.terraformrc`)?**

A configuration file on the developer workstation or CI runner managing plugin cache directories, credentials helpers, and provider installation mirrors.
</Step>

<Step>
**What is Terraform Plugin Cache Directory (`TF_PLUGIN_CACHE_DIR`)?**

Caching downloaded provider binaries locally on disk across multiple directories, saving gigabytes of bandwidth and minutes of CI build time.
</Step>

<Step>
**What is Policy as Code Shift-Left Testing?**

Executing OPA/Checkov linters directly in pre-commit hooks and PR builds to catch compliance violations before code is merged to `main`.
</Step>

<Step>
**What is Terraform JSON Syntax (`*.tf.json`)?**

Allowing Terraform configurations to be written in standard JSON rather than HCL, useful for machine-generated infrastructure templates.
</Step>

<Step>
**What is Pulumi Automation API?**

An SDK that embeds Pulumi infrastructure provisioning directly inside application code (e.g., a SaaS app provisioning tenant databases programmatically in Go).
</Step>

<Step>
**What is Crossplane Environment Config?**

Injecting shared global configuration variables (AWS Account IDs, environment names) dynamically into Crossplane Compositions.
</Step>

<Step>
**What is Ansible Fact Gathering (`setup` module)?**

Automatically discovering hardware, OS, network, and disk facts from target hosts upon playbook execution and storing them in `ansible_facts`.
</Step>

<Step>
**What is Terraform `terraform_version` Constraint?**

Locking configurations to compatible engine versions (`required_version = ">= 1.5.0, < 2.0.0"`) to prevent syntax incompatibility issues.
</Step>
